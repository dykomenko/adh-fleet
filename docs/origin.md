# Origin-нода (main)

Настраивается один раз. Дальше вы сюда заходите только чтобы поменять фильтры.

По тексту origin — нода с именем `node01`. Подставьте своё.

---

## 1. Консоль Netbird

Один раз, до того как трогать серверы. `app.netbird.io`:

1. **Группы** — `agh-origin` и `agh-replica`.

2. **Два setup key**, оба с auto-assign нужной группы:
   - для origin — auto-assign `agh-origin`, хватит одноразового;
   - для реплик — тип **Reusable**, auto-assign `agh-replica`, срок с запасом.

   Так группа назначается автоматически при подключении, и руками в консоли
   ничего трогать не нужно.

3. **Истечение пиров — отключить.** Иначе через заданный срок ноды потребуют
   повторной интерактивной авторизации, и весь парк одновременно выпадет
   из оверлея. Снять и в настройках ключа, и в свойствах пиров.

4. **Политика доступа** — одно правило: `agh-origin` → `agh-replica`,
   протокол **TCP**, порт **3000**. Больше ничего открывать не нужно.

   Дефолтное правило `All → All` удалить. Оно оперирует группой `All` и потому
   не видно на вкладке Policies внутри группы — проверяйте на общей странице
   Access Control. Пока оно живо, ваша политика ничего не ограничивает.

Ключи положите в `.env` на рабочей машине, в одинарных кавычках.

## 2. Оверлей

```bash
curl -fsSL https://pkgs.netbird.io/install.sh | sh
netbird up --management-url https://api.netbird.io:443 \
  --setup-key "$NB_KEY_ORIGIN" --hostname node01 \
  --disable-dns --dns-resolver-address 127.0.0.1:5053
```

**Нужны оба DNS-флага** — проверено на netbird 0.78.2:

- `--disable-dns` запрещает агенту править настройки DNS системы, но его
  локальный резолвер при этом всё равно поднимается и **занимает порт 53**
  на оверлейном адресе — тот самый, который нужен AdGuard Home;
- `--dns-resolver-address` уводит резолвер на другой порт. Только он реально
  освобождает 53-й.

Порт 5053 — из примера в справке netbird. 5353 тоже работает, но это порт
mDNS, и на образах с avahi может конфликтовать.

`--management-url` указывается **явно**: без него агент берёт адрес
из унаследованного состояния, и по выводу этого не понять.

```bash
netbird status -d | grep -iE 'management|fqdn'
ss -ulnp | grep ':53 ' || echo "порт 53 свободен"
```

Плата за отключение DNS — имена вида `node07.netbird.cloud` на нодах
не разрешаются. Поэтому `gen-sync.sh` собирает список реплик по оверлейным
адресам, а не по именам; настраивать для этого ничего не нужно.

<details>
<summary><b>Если Netbird на ноде уже стоял</b></summary>

Частый случай на VPS с историей. Установщик отказывается работать
на запущенной службе, пишет «NetBird service is running» и **выходит с кодом
успеха**, оставляя старый бинарь. А `netbird up` на подключённом агенте
отвечает «Already connected» и не применяет ни ключ, ни флаги.

Признак: порт 53 занят самим агентом, либо FQDN оканчивается незнакомым
доменом, либо `Peers count: 0/0` при живых нодах.

```bash
systemctl stop netbird
curl -fsSL https://pkgs.netbird.io/install.sh | sh
systemctl stop netbird && rm -rf /etc/netbird /var/lib/netbird && systemctl start netbird
netbird up --management-url https://api.netbird.io:443 \
  --setup-key "$NB_KEY_ORIGIN" --hostname node01 \
  --disable-dns --dns-resolver-address 127.0.0.1:5053
```

Удаляется **весь** каталог состояния, а не только `config.json`: в 0.78
у агента появились профили, и конфигурация может лежать в другом месте.

Старый пир останется в консоли отдельной записью — удалите его.
</details>

## 3. Порт 53

```bash
sudo sed -i 's/^#\?DNSStubListener=.*/DNSStubListener=no/' /etc/systemd/resolved.conf
sudo systemctl restart systemd-resolved
sudo ln -sf /run/systemd/resolve/resolv.conf /etc/resolv.conf
```

Третья строка обязательна. Без неё `/etc/resolv.conf` продолжает указывать
на `127.0.0.53`, который после отключения stub-listener больше не слушает,
и нода остаётся без резолвинга: перестанут работать `apt`, `docker pull`
и сам AGH.

```bash
getent hosts github.com && (sudo ss -ulnp | grep ':53 ' || echo "порт 53 свободен")
```

## 4. AdGuard Home

```bash
sudo install -d /opt/adguardhome
curl -fsSL https://raw.githubusercontent.com/dykomenko/adh-fleet/main/node/docker-compose.yml \
  | sudo tee /opt/adguardhome/docker-compose.yml > /dev/null
cd /opt/adguardhome && sudo docker compose up -d
```

### Firewall — до завершения мастера

С `0.0.0.0` нода становится открытым резолвером на публичном адресе. Такие
находят за часы: в наших тестах порт 3000 начали сканировать через минуту
после открытия. Правила применяем **прежде** чем завершить мастер.

```bash
RAW=https://raw.githubusercontent.com/dykomenko/adh-fleet/main

# сеть клиентов, если туннель раздаёт им адреса; для Xray строка не нужна
echo 'CLIENT_NET=10.101.0.0/24' | sudo tee /etc/adh-firewall.conf

sudo curl -fsSL "$RAW/node/adh-firewall.sh" -o /usr/local/sbin/adh-firewall.sh && \
sudo curl -fsSL "$RAW/node/adh-firewall.service" -o /etc/systemd/system/adh-firewall.service && \
sudo chmod 755 /usr/local/sbin/adh-firewall.sh

sudo systemctl daemon-reload
sudo systemctl enable --now adh-firewall.service
sudo iptables -L ADH-INPUT -n -v
```

Чистый iptables, без ufw: на нодах его обычно нет. **Политика `INPUT`
не меняется** — заводится отдельная цепочка `ADH-INPUT` ровно для портов 53
и 3000, поэтому правила уже настроенного VPN остаются нетронутыми, а SSH
не затрагивается вообще и отрезать себе доступ невозможно.

Правила iptables живут в памяти ядра, поэтому юнит накатывает их при каждой
загрузке, до старта docker. Закрывается и IPv6: без `ip6tables` нода осталась
бы открытым резолвером по шестой версии, что легко упустить.

**Не пишите эти файлы через `tee`.** При неудачном `curl` файл всё равно
создаётся, только пустым, а юнит нулевой длины systemd считает
замаскированным — `enable` падает с «Unit file is masked», и причина выглядит
никак не связанной с загрузкой.

### Мастер установки — единственный раз за проект

```bash
ssh -L 3000:127.0.0.1:3000 user@node01
```

На `http://localhost:3000`:

- **Веб-интерфейс** — **«Все интерфейсы»**, порт `3000`
- **DNS-сервер** — **«Все интерфейсы»**, порт `53`
- **Логин `admin` и пароль** — пароль станет общим для всего парка

**Оба поля — именно «Все интерфейсы».** Если выбрать конкретный адрес
для панели, мастер упрётся в самого себя: во время установки AGH уже слушает
`0.0.0.0:3000`, и проверка доступности того же порта на конкретном адресе
натыкается на его собственный сокет.

Вторая причина важнее: адреса у нод разные, и привязка к адресу origin
сделала бы шаблон непригодным для реплик. `make-template.sh` откажется
снимать такой шаблон.

Привязка DNS к адресу шлюза не годится по той же логике: интерфейс туннеля
появляется и исчезает при рестартах, и если он поднялся позже AGH, тот
не стартует вовсе. Доступ ограничивает firewall, а не bind-адрес.

## 6. Снять шаблон

Шаблон — это то, что позволяет репликам ставиться одной командой.

```bash
curl -fsSL https://raw.githubusercontent.com/dykomenko/adh-fleet/main/scripts/make-template.sh \
  -o /tmp/mt.sh
sudo bash /tmp/mt.sh
```

Скрипт напечатает **bcrypt-хеш пароля** — это `AGH_PASS_HASH` для установки
нод, положите его в `.env` в одинарных кавычках. Сам шаблон заберите
на рабочую машину и закоммитьте:

```bash
scp node01:/tmp/AdGuardHome.yaml.tmpl node/AdGuardHome.yaml.tmpl
git add node/AdGuardHome.yaml.tmpl && git commit -m "Обновить шаблон" && git push
```

Секретов в шаблоне нет: адреса заменены на `0.0.0.0`, хеш — плейсхолдером,
а фильтры и `user_rules` вырезаны — они приезжают синхронизацией. Скрипт
проверяет результат и откажется писать шаблон, в котором осталась привязка
к адресу ноды или хоть один bcrypt-хеш.

Переснимать нужно только при смене пароля админа.

## 7. Синхронизатор

```bash
AGH_PASS='ПАРОЛЬ' sudo -E bash <(curl -fsSL https://raw.githubusercontent.com/dykomenko/adh-fleet/main/origin/setup-origin.sh)
```

**Здесь нужен пароль открытым текстом**, а не хеш из шага 6. Названия похожие,
поэтому коротко о разнице:

| Переменная | Что подставлять | Куда попадает |
|---|---|---|
| `AGH_PASS` | пароль открытым текстом | `/opt/agh-sync/admin.pass` на origin |
| `AGH_PASS_HASH` | bcrypt-хеш | секция `users:` в конфиге реплики |

Хеш создаёт учётку на ноде, открытый пароль позволяет синхронизатору ею
воспользоваться: AGH хранит пароли только хешированными, а его API принимает
пароль. Скрипт откажется работать, если передать ему хеш.

Если реплик ещё нет, скрипт скажет об этом и выйдет — поднимите первую ноду
и запустите `/opt/agh-sync/sync-now.sh`.

## Эксплуатация

**Правки только здесь.** Изменение на реплике будет затёрто при следующем
прогоне.

**Синхронизация — раз в час.** Нужно немедленно:

```bash
/opt/agh-sync/sync-now.sh
```

Он пересоберёт список реплик и запустит прогон сразу, показав логи.

**Обновление парка** — `scripts/fleet-update.sh` с рабочей машины, не отсюда.
На origin намеренно нет ssh-доступа к остальным нодам: компрометация origin
не должна открывать весь парк.

**Бэкап.** Реальная конфигурация существует в одном экземпляре — здесь:

```bash
tar czf agh-$(date +%F).tar.gz -C /opt/adguardhome conf
```

## Если что-то пошло не так

<details>
<summary><b>Синхронизатор пишет 401 Unauthorized</b></summary>

Учётки разошлись: на реплике лежит хеш не от того пароля, что в `admin.pass`.
Сравните напрямую, на обеих нодах:

```bash
grep -A2 '^users:' /opt/adguardhome/conf/AdGuardHome.yaml
```

Типичные причины: реплику ставили с неверным `AGH_PASS_HASH` (сейчас
`install.sh` такое отклоняет) либо пароль на origin меняли после снятия
шаблона. Починка на реплике:

```bash
sed -i 's|^    password: .*|    password: ХЕШ_С_ORIGIN|' \
  /opt/adguardhome/conf/AdGuardHome.yaml
docker restart adguardhome
```

Кавычки одинарные: в хеше есть `$`.
</details>

<details>
<summary><b>Смена пароля админа</b></summary>

Это операция на весь парк. Синхронизатор сам её не разнесёт: чтобы разослать
новый пароль, ему нужно сначала авторизоваться старым.

Порядок: сменить пароль на origin → переснять шаблон (`make-template.sh`) →
обновить `AGH_PASS_HASH` в `.env` и шаблон в репозитории → обновить
`admin.pass` на origin → поправить хеш на каждой уже стоящей реплике.
</details>

<details>
<summary><b>Список реплик пуст</b></summary>

```bash
netbird status | grep -i 'peers count'
```

Ноль пиров — реплики не подключены к оверлею либо ушли в другой аккаунт.
Сверьте management-сервер на обеих нодах.

Пиры есть, а список пуст — запустите генератор вручную, он печатает источник
отбора:

```bash
/opt/agh-sync/gen-sync.sh
```

Отбор по группе `agh-replica` работает, только если CLI netbird отдаёт членство
в группах. На 0.78.2 он его не отдаёт, поэтому генератор переходит к запасному
способу — берёт всех пиров оверлея. Это корректно, пока в аккаунте только ноды
AGH.
</details>

<details>
<summary><b>Реплика отстала</b></summary>

```bash
docker logs agh-sync
grep -c '^  - url:' /opt/agh-sync/sync.yaml
netbird status --json | jq -r '.peers.details[]? | .netbirdIp'
```

Реплики записаны оверлейными адресами, а не именами. Проверить конкретную:

```bash
curl -su admin:ПАРОЛЬ http://100.x.x.x:3000/control/status
```
</details>

<details>
<summary><b>Контейнер agh-sync не стартует</b></summary>

Если в логах `permission denied` на `/config/sync.yaml` — контейнер работает
не от root и не может прочитать файл с правами 600. В compose должно быть
`user: "0:0"`. Ослаблять права файла нельзя: в нём пароль админа всего парка.

Если вместо работы печатается справка по флагам — конфиг невалиден или
недоступен, смотрите последнюю строку вывода.
</details>

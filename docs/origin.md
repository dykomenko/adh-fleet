# Origin-нода (main)

Единственная нода, которую вы настраиваете руками. Здесь живут фильтры,
синхронизатор и генератор списка реплик. Всё остальное в парке — производное
от неё.

Дальше по тексту origin — это `node01` со шлюзом VPN `10.101.0.1`.
Подставьте свои значения.

---

## 0. Консоль Netbird

Делается один раз, до того как трогать серверы. `app.netbird.io`:

1. **Группы** — завести `agh-origin` и `agh-replica`. На них завязано
   и разграничение доступа, и автообнаружение реплик.
2. **Setup key** — тип **Reusable** (по умолчанию предлагается одноразовый),
   auto-assign groups → `agh-replica`. Срок жизни с запасом: когда ключ
   истечёт, установка новых нод начнёт молча отваливаться.
3. **Истечение пиров — отключить.** С включённым peer expiration ноды через
   заданный срок потребуют повторной интерактивной авторизации, и весь парк
   одновременно выпадет из оверлея. Снять и в настройках ключа, и в свойствах
   пиров.
4. **Политика доступа** — завести одно правило: `agh-origin` → `agh-replica`,
   протокол **TCP**, порты **3000** и **22**. Направление одностороннее:
   реплики не должны видеть ни друг друга, ни origin.

   Порт 3000 — панель AGH, куда ходит синхронизатор. Порт 22 нужен
   `fleet-update.sh`: он запускается на origin и ходит по SSH на ноды по их
   оверлейным именам. Не открывать 22 можно, но тогда обновлять парк придётся
   иначе — с рабочей машины список нод не получить, `netbird status` работает
   только у члена оверлея.

   **Дефолтное правило удалить.** Оно оперирует группой `All`, поэтому
   на вкладке Policies внутри группы `agh-origin` не отображается — проверяйте
   на общей странице Access Control. Пока правило `All → All` живо, сужение
   вашей политики ничего не даёт.

Ключ положите в `.env` в корне проекта (файл в git не попадает):

```
NB_KEY=...
```

## 1. Оверлей и порт 53

```bash
curl -fsSL https://pkgs.netbird.io/install.sh | sh
netbird up --setup-key "$NB_KEY" --hostname node01 --disable-dns
```

`--disable-dns` обязателен: агент оверлея иначе правит `/etc/resolv.conf`,
а на DNS-сервере это ровно то, чего быть не должно. Точное имя флага сверьте
через `netbird up --help` — между версиями оно переименовывалось.

Группу `agh-origin` этой ноде назначьте в консоли вручную: setup key раздаёт
`agh-replica`.

```bash
sudo sed -i 's/^#\?DNSStubListener=.*/DNSStubListener=no/' /etc/systemd/resolved.conf
sudo systemctl restart systemd-resolved
```

Проверка: `sudo ss -ulnp | grep :53` должен молчать.

## 2. Контейнер AGH

Скопируйте `node/docker-compose.yml` из репозитория в `/opt/adguardhome/`
и поднимите:

```bash
cd /opt/adguardhome && docker compose up -d
```

`network_mode: host` обязателен. В bridge-режиме Docker занатит трафик, AGH
увидит все запросы как приходящие с адреса docker-шлюза, и статистика
с персональными правилами по клиентам сломается.

---

## 3. Мастер установки — единственный раз за весь проект

```bash
ssh -L 3000:127.0.0.1:3000 user@node01
```

На `http://localhost:3000`:

- **DNS-сервер** — `10.101.0.1`, порт `53`
- **Веб-интерфейс** — адрес ноды в оверлее (`netbird status` покажет), порт `3000`
- **Логин и пароль админа** — пароль станет общим для всего парка, запишите его

Мастер слушает все интерфейсы, поэтому туннель на `127.0.0.1` здесь работает.
После сохранения панель переедет на оверлейный адрес, и заходить нужно будет
через `ssh -L 3000:<оверлейный-адрес>:3000 user@node01`.

---

## 4. Фильтрация

Всё заданное здесь разъедется по репликам автоматически: списки блокировок,
пользовательские правила, апстримы, fallback-серверы, rewrites, сервисы,
персональные клиенты.

Апстримы для примера: `https://dns.quad9.net/dns-query`, bootstrap `9.9.9.10`.

**Про персональных клиентов.** У одного человека на разных нодах разные адреса
(`10.101.0.5`, `10.117.0.5` и т.д.). В карточке клиента AGH перечисляется
несколько идентификаторов сразу — впишите все возможные адреса. Если клиенты
кочуют между нодами произвольно, рассмотрите ClientID через DoT или DoH:
иначе список идентификаторов станет неуправляемым.

## 5. Снять шаблон

Это то, что превращает установку реплики в одну команду. Если готовый
`AdGuardHome.yaml` лежит на месте до первого старта, AGH не показывает мастер
вовсе.

Писать шаблон руками не надо — он снимается с работающей ноды, так вы не
гадаете про `schema_version` и формат полей текущей версии AGH:

```bash
VPN_GW=10.101.0.1 sudo -E ./make-template.sh
```

Заберите результат на рабочую машину:

```bash
scp node01:/opt/adguardhome/AdGuardHome.yaml.tmpl node/AdGuardHome.yaml.tmpl
```

**Шаблон содержит bcrypt-хеш пароля админа.** Именно поэтому пароль на всех
нодах совпадает без ручного ввода — и именно поэтому файл в `.gitignore`
и не должен попадать ни в репозиторий, ни куда-либо ещё.

## 6. Синхронизатор

Скопируйте `origin/docker-compose.yml` в `/opt/agh-sync/`, положите рядом
пароль и генератор:

```bash
sudo install -d /opt/agh-sync
sudo install -m 600 /dev/null /opt/agh-sync/admin.pass
printf '%s' 'ПАРОЛЬ' | sudo tee /opt/agh-sync/admin.pass > /dev/null
sudo install -m 700 gen-sync.sh /opt/agh-sync/gen-sync.sh
```

`sync.yaml` руками не пишется — его собирает генератор. Первый прогон:

```bash
sudo /opt/agh-sync/gen-sync.sh
```

Затем поднимаем синхронизатор и ставим генератор в крон:

```bash
cd /opt/agh-sync && sudo docker compose up -d
```

```bash
echo '*/15 * * * * root /opt/agh-sync/gen-sync.sh' | sudo tee /etc/cron.d/agh-sync-gen
```

С этого момента добавление ноды не требует на origin ни одной правки.

## Эксплуатация

**Правки только здесь.** Любое изменение на реплике будет затёрто при следующем
прогоне синхронизации.

**Обновление парка** — `scripts/fleet-update.sh` с origin. Все ноды в одном
окне: пока версии разные, синхронизатор может спотыкаться на расхождении API.

**Точка отката.** Тег `latest` сам по себе вернуться назад не даёт, поэтому
перед обновлением зафиксируйте образ:

```bash
docker inspect --format '{{index .RepoDigests 0}}' adguardhome
```

Полученный `adguard/adguardhome@sha256:…` подставляется вместо тега в compose,
если релиз окажется неудачным.

**Бэкап.** Реальная конфигурация существует в одном экземпляре — здесь.
Тридцать реплик восстанавливаются из неё одним прогоном синхронизации:

```bash
tar czf agh-$(date +%F).tar.gz -C /opt/adguardhome conf AdGuardHome.yaml.tmpl
```

**Если реплика отстала:**

```bash
docker logs agh-sync
grep node07 /opt/agh-sync/sync.yaml
curl -su admin:ПАРОЛЬ http://node07:3000/control/status
```

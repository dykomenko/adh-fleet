AdGuard Home на каждой ноде

AGH на всех VPN-серверах, фильтры синхронизируются с одной origin-ноды. Единой точки отказа нет. Новая нода — одна команда.

Шпаргалка

то, что действительно набирается

Четыре команды покрывают всю повседневную работу с парком. Остальное в этом документе — разовая настройка origin и разбор поломок, читается по надобности.

Поднять новую реплику

на самой ноде, root 
NB_KEY_REPLICA='...' AGH_PASS_HASH='...' \
  bash <(curl -fsSL https://raw.githubusercontent.com/dykomenko/adh-fleet/main/install.sh) HK01

Меняется только имя в конце. Значения — из .env под теми же именами. После этого остаётся один ручной шаг: убрать секцию dns из конфига Xray в панели Remnawave.

Открыть панель любой ноды

с рабочей машины 
ssh -L 3000:127.0.0.1:3000 root@HK01

Дальше http://localhost:3000, логин admin. Для второй ноды одновременно — другой локальный порт: -L 3001:127.0.0.1:3000.

Разослать правила немедленно

на origin 
/opt/agh-sync/sync-now.sh

Обычный график — раз в час. Эта команда пересобирает список реплик и прогоняет синхронизацию сразу, показывая логи.

Обновить AGH на парке

с рабочей машины 
./scripts/fleet-update.sh HK01 HK02 HK03

Без аргументов берёт хосты из NODES в .env. Запускается не с origin намеренно — там нет ssh-доступа к парку.

Где взять значения для .env
  • NB_KEY_ORIGIN, NB_KEY_REPLICA — два setup key из консоли Netbird, с auto-assign групп agh-origin и agh-replica;
  • AGH_PASS_HASH — bcrypt-хеш пароля админа, печатает make-template.sh на origin.

Значения берите в одинарные кавычки: в хеше есть $, без них оболочка съест часть строки.

Ключи не взаимозаменяемы. С origin-ключом реплика попадёт в группу agh-origin, синхронизатор её не найдёт, а установка при этом пройдёт без единой ошибки.

Как это устроено

Падение любой ноды задевает только её клиентов, у которых в этот момент всё равно нет туннеля.

Xray: две обязательные половины

Чтобы фильтрация дошла до клиентов, нужны обе — по отдельности не работает ни одна, а симптом одинаковый: в журнале AGH только ваши собственные проверки и ни одного клиентского домена.

1. В конфиге Xray нет секции dns. Пока она есть, Xray резолвит встроенным резолвером через прописанные там серверы и системный не спрашивает вовсе. 2. /etc/resolv.conf указывает на 127.0.0.1 — это делает install.sh.

Почему AGH слушает 0.0.0.0, а не адрес туннеля

Интерфейс туннеля появляется и исчезает при рестартах. Если он поднялся позже AGH, тот не стартует вовсе. Плюс на свежем сервере, где VPN ещё не поднят, такого адреса в списке мастера просто нет.

Доступ ограничивает firewall: отдельная цепочка ADH-INPUT ровно для портов 53 и 3000. Политика INPUT не меняется, поэтому правила уже настроенного VPN остаются нетронутыми, а SSH не затрагивается вообще — отрезать себе доступ невозможно.

Порт 53 открыт с localhost; если туннель раздаёт клиентам адреса, вторым аргументом install.sh передаётся их сеть. Порт 3000 — только с интерфейса оверлея. Правила живут в памяти ядра, поэтому юнит накатывает их при каждой загрузке, до старта docker.

Что эта схема не даёт

Сводной статистики и единого лога запросов: и то, и другое остаётся на каждой ноде своим. Это прямая плата за отсутствие единой точки отказа. Нужна сводная картина — снимайте её отдельно через API статистики AGH в Prometheus или ClickHouse.

Развернуть origin

один раз за весь проект

Единственная нода, которую вы настраиваете руками. Дальше сюда заходят только чтобы поменять фильтры.

  1. Консоль Netbird

    Четыре вещи, до того как трогать серверы:

    • группы agh-origin и agh-replica;
    • два setup key с auto-assign нужной группы — для реплик тип Reusable;
    • истечение пиров отключить, иначе через месяц весь парк одновременно выпадет из оверлея;
    • политика agh-origin → agh-replica, TCP, порт 3000. Дефолтное All → All удалить.
    Дефолтное правило прячется

    Оно оперирует группой All и потому не видно на вкладке Policies внутри группы — проверяйте на общей странице Access Control. Пока оно живо, ваша политика ничего не ограничивает.

  2. Оверлей и порт 53

    bashorigin
    curl -fsSL https://pkgs.netbird.io/install.sh | sh

netbird up --management-url https://api.netbird.io:443 \
  --setup-key "$NB_KEY_ORIGIN" --hostname node01 \
  --disable-dns --dns-resolver-address 127.0.0.1:5053

sed -i 's/^#\?DNSStubListener=.*/DNSStubListener=no/' /etc/systemd/resolved.conf
systemctl restart systemd-resolved
ln -sf /run/systemd/resolve/resolv.conf /etc/resolv.conf

ss -ulnp | grep ':53 ' || echo "порт 53 свободен"
    Зачем два DNS-флага и почему обязательна строка про resolv.conf

    --disable-dns запрещает агенту править настройки DNS системы, но его локальный резолвер всё равно поднимается и занимает порт 53 — тот самый, который нужен AGH. Освобождает порт только --dns-resolver-address. Проверено на netbird 0.78.2.

    Строка с ln -sf обязательна: без неё /etc/resolv.conf продолжает указывать на 127.0.0.53, который после отключения stub-listener больше не слушает. Нода остаётся без резолвинга — перестают работать apt, docker pull и сам AGH.

    --management-url указывается явно: без него агент берёт адрес из унаследованного состояния, и по выводу этого не понять.

  3. Firewall — до запуска AGH

    bashorigin
    RAW=https://raw.githubusercontent.com/dykomenko/adh-fleet/main

echo 'CLIENT_NET=' > /etc/adh-firewall.conf

curl -fsSL "$RAW/node/adh-firewall.sh" -o /usr/local/sbin/adh-firewall.sh && \
curl -fsSL "$RAW/node/adh-firewall.service" -o /etc/systemd/system/adh-firewall.service && \
chmod 755 /usr/local/sbin/adh-firewall.sh

systemctl daemon-reload
systemctl enable --now adh-firewall.service
iptables -L ADH-INPUT -n -v

    В CLIENT_NET впишите сеть клиентов, если туннель раздаёт им адреса. Для Xray оставьте пустым.

    Не пишите эти файлы через tee

    При неудачном curl файл всё равно создаётся, только пустым. Юнит нулевой длины systemd считает замаскированным, и enable падает с «Unit file is masked» — сообщение никак не указывает на исходную причину.

  4. AdGuard Home и мастер установки

    bashorigin
    install -d /opt/adguardhome
curl -fsSL "$RAW/node/docker-compose.yml" -o /opt/adguardhome/docker-compose.yml
cd /opt/adguardhome && docker compose up -d
    bashрабочая машина
    ssh -L 3000:127.0.0.1:3000 root@node01

    На http://localhost:3000: оба поля — «Все интерфейсы», порты 3000 и 53, логин admin. Пароль станет общим для всего парка.

    Именно «Все интерфейсы», оба поля

    Если выбрать для панели конкретный адрес, мастер упрётся в самого себя: во время установки AGH уже слушает 0.0.0.0:3000, и проверка того же порта на конкретном адресе натыкается на его собственный сокет.

    Важнее второе: адреса у нод разные, и привязка к адресу origin сделала бы шаблон непригодным для реплик.

    Здесь же настройте фильтры, блок-листы и апстримы — это единственное место, где вы это делаете.

  5. Снять шаблон

    bashorigin
    curl -fsSL "$RAW/scripts/make-template.sh" -o /tmp/mt.sh && bash /tmp/mt.sh

    Скрипт напечатает bcrypt-хеш пароля — это AGH_PASS_HASH для установки нод, положите его в .env. Шаблон заберите на рабочую машину и закоммитьте в node/AdGuardHome.yaml.tmpl.

    Почему шаблон можно держать в публичном репозитории

    Секретов в нём нет: адреса заменены на 0.0.0.0, хеш пароля — плейсхолдером, а фильтры и user_rules вырезаны, потому что приезжают синхронизацией. Скрипт проверяет результат и откажется писать шаблон, в котором осталась привязка к адресу ноды или хоть один bcrypt-хеш.

    Именно поэтому установка реплики сводится к одной команде: нода тянет с GitHub всё, что ей нужно, и ничего не приходится класть на неё заранее.

  6. Синхронизатор

    bashorigin
    AGH_PASS='ПАРОЛЬ' bash <(curl -fsSL "$RAW/origin/setup-origin.sh")

    Здесь нужен пароль открытым текстом, а не хеш из прошлого шага. Скрипт откажется работать, если передать ему хеш.

    В чём разница между AGH_PASS и AGH_PASS_HASH
    ПеременнаяЧто подставлятьКуда попадает
    AGH_PASSпароль открытым текстомadmin.pass на origin
    AGH_PASS_HASHbcrypt-хешсекция users на реплике

    Хеш создаёт учётку на ноде, открытый пароль позволяет синхронизатору ею воспользоваться: AGH хранит пароли только хешированными, а его API принимает пароль.

    Если реплик ещё нет, скрипт скажет об этом и выйдет — это ожидаемо.

Безопасность выходной ноды

правится в конфиге Xray

Клиент, подключённый к ноде, выходит в интернет с её адреса — а значит может обратиться и к её внутренним сервисам. Firewall тут не помощник: запросы приходят изнутри.

Закрывается на стороне Xray. В routing.rules первым правилом:

jsonшаблон конфига в Remnawave
{
  "type": "field",
  "ip": ["geoip:private"],
  "outboundTag": "block"
}

Это отсекает клиентам не только панель AGH, но и всё внутреннее на ноде — Docker-сети, оверлей, метрики, сам remnanode.

Проверка с подключённого клиента

bashклиент в VPN
curl -m 5 -o /dev/null -w "публичный: %{http_code}\n" http://ПУБЛИЧНЫЙ_IP:3000/
curl -m 5 -o /dev/null -w "оверлей:   %{http_code}\n" http://100.x.x.x:3000/
curl -m 5 -o /dev/null -w "localhost: %{http_code}\n" http://127.0.0.1:3000/

Все три должны дать таймаут или 000. Любой 200 или 302 означает, что панель достижима.

Что означает каждый из трёх адресов

Публичный IP ответил — правило firewall не применилось, смотрите iptables -L ADH-INPUT -n -v.

Оверлейный адрес ответил — ваш клиент вышел через ноду, которой Netbird разрешает достучаться до целевой. По политике agh-origin → agh-replica такое возможно, если выходная нода origin. Netbird отработал правильно, дыра не в нём.

127.0.0.1 ответил — самый неочевидный случай. При настройке клиента через SOCKS или HTTP-прокси браузер отдаёт адрес прокси как есть, и Xray подключается к 127.0.0.1:3000 на самой ноде. С её точки зрения это обычное локальное соединение, которое firewall обязан разрешать — оно нужно синхронизатору и вашему ssh-туннелю. Поэтому закрывать надо именно правилом Xray.

Если что-то пошло не так

всё, обо что споткнулись при развёртывании

Случаи ниже объединяет одно свойство: нода выглядит исправной. Ошибки нет, команды отрабатывают, контейнеры поднимаются — а схема не работает. Поэтому у каждого указан признак, по которому он опознаётся.

Клиенты не фильтруются, в журнале AGH только ваши проверки

Отвалилась одна из двух половин. Какая именно — покажет захват трафика при подключённом клиенте:

bashнода
apt-get install -y tcpdump
timeout 25 tcpdump -ni any 'port 53 or port 853' -c 40
  • запросы на 127.0.0.1.53 — всё правильно;
  • запросы с публичного адреса ноды на 8.8.8.8, 1.1.1.1 или порт 853 — в конфиге Xray осталась секция dns. Соединения на 853-й доказывают это сами: DoT умеет только встроенный резолвер Xray, системный — нет.

И проверьте резолвер ноды: cat /etc/resolv.conf должен показать nameserver 127.0.0.1 в обычном файле, а не символьную ссылку — пока это ссылка, systemd-resolved перезапишет содержимое.

Не проверяйте личным устройством

Локальный блокировщик в браузере или свой DNS дадут ложноположительный результат, и нода будет выглядеть рабочей, не будучи ею. Надёжный признак — журнал запросов в панели AGH: там должны появляться домены, которые запрашивают клиенты.

На ноде уже был установлен Netbird

Установщик отказывается работать на запущенной службе, пишет «NetBird service is running» и выходит с кодом успеха, оставляя старый бинарь. А netbird up на подключённом агенте отвечает «Already connected» и не применяет ни ключ, ни флаги.

Признаки: порт 53 занят самим агентом; FQDN оканчивается незнакомым доменом; Peers count: 0/0 при живых нодах.

bashнода
systemctl stop netbird
curl -fsSL https://pkgs.netbird.io/install.sh | sh

systemctl stop netbird
rm -rf /etc/netbird /var/lib/netbird
systemctl start netbird

netbird up --management-url https://api.netbird.io:443 \
  --setup-key <КЛЮЧ> --hostname HK01 \
  --disable-dns --dns-resolver-address 127.0.0.1:5053

Удаляется весь каталог состояния: в 0.78 у агента появились профили, и конфигурация может лежать не в config.json. install.sh делает это сам.

Синхронизатор пишет 401 Unauthorized

Учётки разошлись: на реплике хеш не от того пароля, что в admin.pass. Сравните на обеих нодах:

bashorigin и реплика
grep -A2 '^users:' /opt/adguardhome/conf/AdGuardHome.yaml

Починка на реплике — кавычки одинарные, в хеше есть $:

bashреплика
sed -i 's|^    password: .*|    password: ХЕШ_С_ORIGIN|' \
  /opt/adguardhome/conf/AdGuardHome.yaml
docker restart adguardhome

Смена пароля админа — операция на весь парк. Синхронизатор сам её не разнесёт: чтобы разослать новый пароль, ему нужно авторизоваться старым. Порядок: сменить на origin → переснять шаблон → обновить .env и репозиторий → обновить admin.pass → поправить хеш на каждой реплике.

Список реплик пуст
bashorigin
netbird status | grep -i 'peers count'
/opt/agh-sync/gen-sync.sh

Ноль пиров — реплики не подключены к оверлею либо ушли в другой аккаунт. Пиры есть, а список пуст — генератор печатает источник отбора, смотрите по нему.

Отбор по группе работает, только если CLI netbird отдаёт членство в группах. На 0.78.2 он его не отдаёт, поэтому генератор берёт всех пиров оверлея. Это корректно, пока в аккаунте только ноды AGH.

Порт 53 занят, AGH не поднимается

Виновника два — systemd-resolved и резолвер netbird. Смотрим, кто именно:

bashнода
ss -ulnp | grep ':53 '

Лечение обоих случаев — в шаге 2 раздела про origin.

systemd пишет «Unit file is masked»

Файл юнита пустой — curl не скачал, а tee всё равно создал.

bashнода
rm -f /etc/systemd/system/adh-firewall.service /usr/local/sbin/adh-firewall.sh
systemctl daemon-reload

Затем повторите загрузку через -o и цепочку &&.

Контейнер agh-sync печатает справку вместо работы

Конфиг невалиден или недоступен — настоящая причина в последней строке вывода. Если там permission denied на /config/sync.yaml, контейнер работает не от root и не может прочитать файл с правами 600. В compose должно быть user: "0:0".

Ослаблять права файла нельзя: в нём пароль админа всего парка.

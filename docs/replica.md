# Реплика

Никакого мастера установки, никакого браузера, никаких правок на origin.
Одна команда с рабочей машины.

---

## Добавить ноду

```bash
./scripts/add-node.sh node07 7
```

Первый аргумент — ssh-хост, второй — номер ноды. Адрес шлюза VPN выводится
из номера по формуле `10.(100+N).0.1`, то есть node07 получает `10.107.0.1`.

Что делает скрипт:

1. читает `NB_KEY` из `.env`;
2. кладёт на ноду `docker-compose.yml` и `AdGuardHome.yaml.tmpl`;
3. передаёт `bootstrap-agh.sh` по ssh на stdin и запускает его там.

Ключ уходит через окружение ssh-сессии и на диске ноды не остаётся.

---

## Что происходит на ноде

`bootstrap-agh.sh` последовательно:

1. ставит агент Netbird и подключает ноду с `--disable-dns`;
2. дожидается адреса в оверлее (до 30 секунд);
3. выключает `DNSStubListener` у systemd-resolved, освобождая порт 53;
4. подставляет в шаблон адрес шлюза и оверлейный адрес — готовый
   `AdGuardHome.yaml` означает, что **мастер установки не запустится**;
5. поднимает контейнер.

Скрипт идемпотентен: повторный запуск на уже поднятой ноде безопасен.

---

## Что происходит дальше само

- Setup key назначает ноде группу `agh-replica`.
- Генератор на origin пересобирает список реплик по этой группе каждые
  15 минут и подхватывает новичка.
- Фильтры приезжают с ближайшим прогоном синхронизации (раз в 10 минут).

Вмешательство не требуется.

---

## Проверка

```bash
ssh node07 'dig @10.107.0.1 doubleclick.net +short'
```

Заблокированный домен должен вернуть `0.0.0.0` либо пустой ответ. Реальный
адрес означает, что фильтры ещё не доехали — подождите прогон.

Нода в списке реплик:

```bash
ssh node01 'grep node07 /opt/agh-sync/sync.yaml'
```

## Клиенты

Каждому клиенту прописывается DNS **его собственной** ноды. Никаких вторых
и запасных DNS: Windows и Android опрашивают перечисленные серверы параллельно,
и фильтрация потечёт постоянно, а не только при аварии.

**WireGuard** — push-механизма нет, адрес подставляется при генерации конфига:

```ini
[Interface]
PrivateKey = ...
Address = 10.107.0.5/32
DNS = 10.107.0.1
```

**OpenVPN:**

```
push "dhcp-option DNS 10.107.0.1"
push "block-outside-dns"
```

`block-outside-dns` нужен Windows-клиентам: без него система продолжит
спрашивать DNS физического интерфейса в обход туннеля.

---

## Убрать ноду из парка

Удалите пир в консоли Netbird. Через 15 минут он исчезнет из `sync.yaml`,
синхронизатор перезапустится с новым составом. Чистить руками ничего не нужно.

---

## Чего на реплике делать нельзя

**Настраивать фильтры, правила, апстримы и клиентов.** Всё это приезжает
с origin, и любая ручная правка будет затёрта при следующем прогоне.
Единственное место для изменений — origin-нода.

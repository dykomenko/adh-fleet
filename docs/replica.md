# Реплика

Одна команда на самой ноде. Ничего не нужно класть заранее, ничего не нужно
менять на origin.

---

## Установка

```bash
NB_KEY='...' AGH_PASS_HASH='...' \
  bash <(curl -fsSL https://raw.githubusercontent.com/dykomenko/adh-fleet/main/install.sh) 7
```

Единственный аргумент — **номер ноды**. Из него выводится адресация:
нода 7 получает сеть `10.107.0.0/24` и DNS `10.107.0.1`.

Оба значения берутся из `.env` на рабочей машине:

- `NB_KEY` — многоразовый setup key Netbird;
- `AGH_PASS_HASH` — bcrypt-хеш пароля админа, его печатает `make-template.sh`
  на origin.

Это хеш, а не пароль: подсмотревший команду не получит доступ к панели.

---

## Что делает скрипт

1. ставит агент Netbird и подключает ноду с `--disable-dns`;
2. дожидается адреса в оверлее (до 30 секунд);
3. выключает `DNSStubListener` у systemd-resolved, освобождая порт 53;
4. тянет с GitHub `docker-compose.yml` и шаблон конфига, подставляет адреса
   и хеш пароля;
5. поднимает контейнер.

Готовый `AdGuardHome.yaml` на месте означает, что **мастер установки
не запустится**. Скрипт идемпотентен — повторный запуск безопасен.

---

## Что происходит дальше само

- Setup key назначает ноде группу `agh-replica`.
- Генератор на origin пересобирает список реплик по этой группе раз в час.
- Фильтры приезжают с ближайшим прогоном синхронизации.

Ждать час не обязательно — на origin есть ручной запуск:

```bash
/opt/agh-sync/sync-now.sh
```

## Проверка

Сразу после установки проверяйте через `127.0.0.1`, а **не** через адрес
шлюза VPN: если туннель на ноде ещё не поднят, такого адреса на ней просто
нет и `dig` упрётся в таймаут.

```bash
dig @127.0.0.1 example.com +short
```

Вернулся адрес — AGH работает. Фильтры при этом ещё пустые: шаблон их
не содержит, они приезжают синхронизацией.

Запустите на origin `/opt/agh-sync/sync-now.sh`, затем:

```bash
dig @127.0.0.1 doubleclick.net +short
```

Теперь заблокированный домен должен вернуть `0.0.0.0` либо пустой ответ.
Реальный адрес означает, что фильтры не доехали.

Когда на ноде поднимете VPN, повторите проверку уже через адрес шлюза —
так вы убедитесь, что клиенты до DNS достучатся:

```bash
dig @10.107.0.1 doubleclick.net +short
```

## Клиенты

Каждому клиенту прописывается DNS **его собственной** ноды. Никаких вторых
и запасных DNS: Windows и Android опрашивают перечисленные серверы параллельно,
и фильтрация потечёт постоянно, а не только при аварии.

**WireGuard** — push-механизма нет, адрес подставляется при генерации конфига:

```ini
[Interface]
PrivateKey = ...
Address = 10.107.0.5/32
DNS = 10.107.0.1
```

**OpenVPN:**

```
push "dhcp-option DNS 10.107.0.1"
push "block-outside-dns"
```

`block-outside-dns` нужен Windows-клиентам: без него система продолжит
спрашивать DNS физического интерфейса в обход туннеля.

---

## Убрать ноду из парка

Удалите пир в консоли Netbird. В течение часа он исчезнет из `sync.yaml`,
синхронизатор перезапустится с новым составом. Чистить руками ничего не нужно.

---

## Чего на реплике делать нельзя

**Настраивать фильтры, правила, апстримы и клиентов.** Всё это приезжает
с origin, и любая ручная правка будет затёрта при следующем прогоне.
Единственное место для изменений — origin-нода.

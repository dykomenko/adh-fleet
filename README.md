# ADH — AdGuard Home на парке VPN-нод

AGH на каждом VPN-сервере, фильтры синхронизируются с одной origin-ноды.
Единой точки отказа нет: падение любой ноды задевает только её собственных
клиентов, у которых в этот момент всё равно нет туннеля.

Связность между origin и репликами — оверлей Netbird. Новая нода ставится
одной командой и попадает в синхронизацию сама.

## Установка реплики

```bash
NB_KEY_REPLICA='...' AGH_PASS_HASH='...' \
  bash <(curl -fsSL https://raw.githubusercontent.com/dykomenko/adh-fleet/main/install.sh) HK01
```

Аргумент — имя ноды, под ним она появится в консоли Netbird. Номеров помнить
не нужно. Если туннель раздаёт клиентам адреса (WireGuard, OpenVPN), вторым
аргументом передаётся их сеть — тогда для неё откроется 53-й порт:

```bash
... install.sh HK01 10.107.0.0/24
```

Для Xray и Remnawave второй аргумент не нужен: клиенты адресов не получают,
DNS запрашивает сам прокси с этой же машины.

Ключей два и они не взаимозаменяемы: `NB_KEY_ORIGIN` с auto-assign группы
`agh-origin` — только для главной ноды, `NB_KEY_REPLICA` с `agh-replica` —
для всех остальных. Имена совпадают с `.env`, переименовывать не нужно.

Аргумент — номер ноды. Всё остальное скрипт делает сам: подключает ноду
к оверлею, освобождает порт 53, разворачивает AGH с готовым конфигом.
Мастер установки не запускается, фильтры приезжают синхронизацией.

Origin настраивается один раз — [docs/origin.md](docs/origin.md).
Подробности по репликам — [docs/replica.md](docs/replica.md).

> Установка реплик заработает после того, как origin настроен и в репозиторий
> закоммичен `node/AdGuardHome.yaml.tmpl` — его печатает `make-template.sh`
> (шаг 5 в docs/origin.md). До этого `install.sh` упрётся в отсутствующий
> шаблон и честно об этом скажет.

## Структура

| Путь | Где работает | Что делает |
|---|---|---|
| `install.sh` | новая нода | ставит AGH одной командой |
| `node/docker-compose.yml` | все ноды | AGH, одинаков везде |
| `node/AdGuardHome.yaml.tmpl` | все ноды | конфиг с плейсхолдерами |
| `origin/setup-origin.sh` | origin | разворачивает синхронизатор |
| `origin/gen-sync.sh` | origin, крон | собирает `sync.yaml` по группе в оверлее |
| `origin/sync-now.sh` | origin, руками | немедленный прогон синхронизации |
| `scripts/make-template.sh` | origin | снимает шаблон конфига |
| `scripts/fleet-update.sh` | рабочая машина | обновляет ноды |

## Доступ к DNS

AGH слушает `0.0.0.0:53`: интерфейс туннеля появляется и исчезает при
рестартах, и привязка к его адресу ломает старт AGH после перезагрузки.
Ограничивает доступ firewall, а не bind-адрес.

Открыт порт всегда с localhost — этого достаточно для Xray и Remnawave,
где резолвит сам прокси с этой же машины. Для WireGuard и OpenVPN
дополнительно открывается сеть клиентов, переданная вторым аргументом.

Если туннельных сетей несколько, держите их **непересекающимися**:
персональные правила в AGH привязаны к IP клиента, и при пересечении
сработают не на тех людях.

## Xray и Remnawave: две обязательные половины

Чтобы фильтрация дошла до клиентов, нужны обе — по отдельности не работает
ни одна:

1. **В конфиге Xray нет секции `dns`.** Пока она есть, Xray резолвит
   встроенным резолвером через прописанные там серверы и системный
   не спрашивает вовсе. Удаляется в шаблоне конфига в панели Remnawave.
2. **`/etc/resolv.conf` на ноде указывает на `127.0.0.1`.** Это делает
   `install.sh`; обычным файлом, а не символьной ссылкой, иначе
   systemd-resolved перезапишет.

Симптом при пропуске любой из них одинаковый: в журнале AGH только ваши
собственные проверки и ни одного клиентского домена.

## Проверка ноды

На самой ноде — работает ли AGH и приехали ли фильтры:

```bash
dig @127.0.0.1 doubleclick.net +short
```

Со стороны клиента — прошла ли фильтрация всю цепочку. Подключитесь к ноде
и откройте <https://adblock.turtlecute.org>: страница прогоняет запросы
к рекламным доменам и показывает, сколько заблокировано.

Вторая проверка единственная, которая охватывает путь целиком — клиент,
туннель, резолвер ноды, AGH, фильтры. На новой ноде её стоит делать
обязательно.

## Вход в панель

Одинаково на origin и на любой реплике — обе слушают `0.0.0.0:3000`, доступ
открыт только с localhost и с интерфейса оверлея:

```bash
ssh -L 3000:127.0.0.1:3000 root@HK01
```

Дальше `http://localhost:3000`, логин `admin`. Нужны две ноды сразу — второй
пробрасывайте на другой локальный порт (`-L 3001:...`).

На репликах панель только для просмотра: правки затрутся синхронизацией.

## Синхронизация

Раз в час — правила меняются редко. Нужно немедленно:

```bash
/opt/agh-sync/sync-now.sh
```

Список реплик пересобирается по составу группы `agh-replica` в оверлее,
тоже раз в час. Добавление или удаление ноды правок на origin не требует.

## Секреты

Репозиторий публичный и секретов не содержит. Раскладка на рабочей машине
устроена так, что попасть в него они и не могут:

```
ADH/
├── .env            ← ключи, ВНЕ репозитория
├── guide/          ← личная копия гайда с подставленными ключами
└── adh-fleet/      ← этот репозиторий
```

- `.env` лежит на уровень выше репозитория — не «в .gitignore», а физически
  вне рабочего дерева;
- `admin.pass` — пароль админа, только на origin, права `600`;
- `node/AdGuardHome.yaml.tmpl` — коммитится намеренно: адреса и bcrypt-хеш
  заменены плейсхолдерами. `make-template.sh` откажется писать шаблон,
  в котором остался хоть один хеш;
- `docs/guide.html` — обезличенная версия гайда, с плейсхолдерами вместо ключей.

Дополнительная страховка — pre-commit хук, отклоняющий коммиты с setup key,
bcrypt-хешем или приватным ключом:

```bash
git config core.hooksPath .githooks
```

На ноды значения попадают через переменные окружения в командной строке
установки и на диске в открытом виде не остаются.

## Разграничение доступа

Политика в Netbird: `agh-origin` → `agh-replica`, TCP, порт 3000.
Односторонняя — реплики не видят ни друг друга, ни origin.

**SSH-доступа к парку на origin нет намеренно.** Обновление нод идёт
с рабочей машины (`scripts/fleet-update.sh`), чтобы компрометация origin
не открывала остальные ноды.

## Что эта схема не даёт

Сводной статистики и единого лога запросов: и то, и другое остаётся на каждой
ноде своим. Это плата за отсутствие единой точки отказа. Нужна сводная картина
— снимайте её отдельно через API статистики AGH в Prometheus или ClickHouse.

## Netbird: нужны оба DNS-флага

Проверено на 0.78.2. `--disable-dns` запрещает агенту править настройки DNS
системы, но его локальный резолвер всё равно поднимается и занимает порт 53
на оверлейном адресе — тот самый, который нужен AdGuard Home. Освобождает
порт только `--dns-resolver-address 127.0.0.1:5053`.

Если агент уже стоял на сервере, установщик откажется работать на запущенной
службе и **выйдет с кодом успеха**, оставив старый бинарь, а `netbird up`
ответит «Already connected» и не применит ни ключ, ни флаги. `install.sh`
это обрабатывает: останавливает службу до установщика и сбрасывает
конфигурацию агента, если резолвер всё равно держит 53.

## Проверить на своей версии

- структура вывода `netbird status --json` — от неё зависит `gen-sync.sh`.
  При расхождении список реплик окажется пустым; генератор это ловит
  и рабочий конфиг не затирает.

# ADH — AdGuard Home на парке VPN-нод

AGH на каждом VPN-сервере, фильтры синхронизируются с одной origin-ноды.
Единой точки отказа нет: падение любой ноды задевает только её собственных
клиентов, у которых в этот момент всё равно нет туннеля.

Связность между origin и репликами — оверлей Netbird. Новая нода ставится
одной командой и попадает в синхронизацию сама.

## Установка реплики

```bash
NB_KEY='...' AGH_PASS_HASH='...' \
  bash <(curl -fsSL https://raw.githubusercontent.com/dykomenko/adh-fleet/main/install.sh) 7
```

Аргумент — номер ноды. Всё остальное скрипт делает сам: подключает ноду
к оверлею, освобождает порт 53, разворачивает AGH с готовым конфигом.
Мастер установки не запускается, фильтры приезжают синхронизацией.

Origin настраивается один раз — [docs/origin.md](docs/origin.md).
Подробности по репликам — [docs/replica.md](docs/replica.md).

> Установка реплик заработает после того, как origin настроен и в репозиторий
> закоммичен `node/AdGuardHome.yaml.tmpl` — его печатает `make-template.sh`
> (шаг 5 в docs/origin.md). До этого `install.sh` упрётся в отсутствующий
> шаблон и честно об этом скажет.

## Структура

| Путь | Где работает | Что делает |
|---|---|---|
| `install.sh` | новая нода | ставит AGH одной командой |
| `node/docker-compose.yml` | все ноды | AGH, одинаков везде |
| `node/AdGuardHome.yaml.tmpl` | все ноды | конфиг с плейсхолдерами |
| `origin/setup-origin.sh` | origin | разворачивает синхронизатор |
| `origin/gen-sync.sh` | origin, крон | собирает `sync.yaml` по группе в оверлее |
| `origin/sync-now.sh` | origin, руками | немедленный прогон синхронизации |
| `scripts/make-template.sh` | origin | снимает шаблон конфига |
| `scripts/fleet-update.sh` | рабочая машина | обновляет ноды |

## Адресация

Выводится из номера ноды, таблица соответствий не ведётся:

```
нода N  →  сеть 10.(100+N).0.0/24,  шлюз и DNS 10.(100+N).0.1
node07  →  10.107.0.0/24,           10.107.0.1
```

Сети обязательно разные: персональные правила в AGH привязаны к IP клиента,
и при пересечении сработают не на тех людях.

## Синхронизация

Раз в час — правила меняются редко. Нужно немедленно:

```bash
/opt/agh-sync/sync-now.sh
```

Список реплик пересобирается по составу группы `agh-replica` в оверлее,
тоже раз в час. Добавление или удаление ноды правок на origin не требует.

## Секреты

Репозиторий публичный и секретов не содержит. Проверяемо:

- `.env` — setup key и хеш пароля, только на рабочей машине, в `.gitignore`;
- `admin.pass` — пароль админа, только на origin, права `600`;
- `node/AdGuardHome.yaml.tmpl` — коммитится намеренно: адреса и bcrypt-хеш
  заменены плейсхолдерами. `make-template.sh` откажется писать шаблон,
  в котором остался хоть один хеш.

На ноды значения попадают через переменные окружения в командной строке
установки и на диске в открытом виде не остаются.

## Разграничение доступа

Политика в Netbird: `agh-origin` → `agh-replica`, TCP, порт 3000.
Односторонняя — реплики не видят ни друг друга, ни origin.

**SSH-доступа к парку на origin нет намеренно.** Обновление нод идёт
с рабочей машины (`scripts/fleet-update.sh`), чтобы компрометация origin
не открывала остальные ноды.

## Что эта схема не даёт

Сводной статистики и единого лога запросов: и то, и другое остаётся на каждой
ноде своим. Это плата за отсутствие единой точки отказа. Нужна сводная картина
— снимайте её отдельно через API статистики AGH в Prometheus или ClickHouse.

## Проверить на своей версии

- имя флага `--disable-dns` у `netbird up` — между версиями переименовывалось,
  сверьте `netbird up --help`. Ошибка здесь ломает DNS на ноде;
- структура вывода `netbird status --json` — от неё зависит `gen-sync.sh`.
  При расхождении список реплик окажется пустым; генератор это ловит
  и рабочий конфиг не затирает.

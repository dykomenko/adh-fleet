# ADH — AdGuard Home на парке VPN-нод

AGH на каждом VPN-сервере, фильтры синхронизируются с одной origin-ноды.
Единой точки отказа нет: падение любой ноды задевает только её собственных
клиентов, у которых в этот момент всё равно нет туннеля.

Связность между origin и репликами — оверлей Netbird. Новая нода поднимается
одной командой и попадает в синхронизацию сама, без правок на origin.

```
origin (node01)                        реплики (node02 … node30)
├── AdGuard Home    ← здесь настраиваются фильтры
├── adguardhome-sync                   └── AdGuard Home
└── gen-sync.sh     → список реплик по группе agh-replica в оверлее
```

## Быстрый старт

```bash
cp .env.example .env    # заполнить NB_KEY
```

1. Настроить origin — [docs/origin.md](docs/origin.md). Один раз, вручную.
2. Снять шаблон конфига на origin, забрать в `node/AdGuardHome.yaml.tmpl`.
3. Добавлять реплики — [docs/replica.md](docs/replica.md):

```bash
./scripts/add-node.sh node07 7
```

## Структура

| Путь | Где работает | Что делает |
|---|---|---|
| `node/docker-compose.yml` | все ноды | AGH, одинаков везде |
| `origin/docker-compose.yml` | origin | adguardhome-sync |
| `origin/gen-sync.sh` | origin, крон | собирает `sync.yaml` по группе в оверлее |
| `scripts/add-node.sh` | рабочая машина | добавляет ноду в парк |
| `scripts/bootstrap-agh.sh` | нода | ставит AGH без мастера установки |
| `scripts/make-template.sh` | origin | снимает шаблон конфига |
| `scripts/fleet-update.sh` | origin | обновляет парк в одном окне |

## Адресация

Выводится из номера ноды, таблица соответствий не ведётся:

```
нода N  →  сеть 10.(100+N).0.0/24,  шлюз и DNS 10.(100+N).0.1
node07  →  10.107.0.0/24,           10.107.0.1
```

Сети обязательно разные: персональные правила в AGH привязаны к IP клиента,
и при пересечении сработают не на тех людях.

## Секреты

В репозиторий не попадают и не должны:

- `.env` — setup key Netbird;
- `node/AdGuardHome.yaml.tmpl` — содержит bcrypt-хеш пароля админа;
- `admin.pass` на origin.

Оба файла в `.gitignore`. Шаблон передаётся на ноды по scp, ключ — через
окружение ssh-сессии.

## Что эта схема не даёт

Сводной статистики и единого лога запросов: и то, и другое остаётся на каждой
ноде своим. Это прямая плата за отсутствие единой точки отказа. Если сводная
картина нужна, снимайте её отдельно через API статистики AGH в Prometheus
или ClickHouse.

## Места, требующие проверки на вашей версии

- имя флага `--disable-dns` у `netbird up` — между версиями переименовывалось,
  сверьте через `netbird up --help`. Ошибка здесь ломает DNS на ноде;
- структура вывода `netbird status --json` — от неё зависит `gen-sync.sh`.
  При расхождении список реплик окажется пустым (генератор это ловит и не
  затирает рабочий конфиг). Для продакшена надёжнее Management API
  `GET /api/peers` с токеном.
